# 05-部署运维

> 生产级登录注册系统 · 部署、日志、监控、备份与 K8s 演进
> 技术栈：Vue 3 + Element Plus / Hyperf (PHP/Swoole) / MySQL 8 / Redis / Docker Compose（可选 Loki 日志栈）。遵守 `设计规范.md` §1.10 配置门禁；安全细节见 `04-安全设计.md`。

## 1. 架构拓扑（Compose 环境）

```
浏览器
  │ HTTPS(生产) / HTTP(dev)
  ▼
nginx (frontend:80) ── 静态资源 + /api 反代 ──▶ backend (hyperf:9501, Swoole)
                                                  │ 同步：MySQL / Redis
                                                  │ 异步：async-queue（Redis 驱动）
                                                  ▼
                                        ┌──────────────────────────────┐
                                        │ 第三方：SMS / Email / OAuth / │
                                        │ KYC / GeoIP / Captcha(可选)   │
                                        └──────────────────────────────┘
 日志侧链：backend/frontend stdout(JSON) → promtail ─▶ loki ─▶ grafana
```

## 2. Compose 服务清单

| 服务 | 镜像 | 端口（dev） | 是否必需 | 说明 |
|---|---|---|---|---|
| mysql | mysql:8.0 | 3306 | ✅ | 字符集 utf8mb4；`lower_case_table_names=1` |
| redis | redis:7-alpine | 6379 | ✅ | 限流计数 / async-queue / 会话辅助；宕机降级 sc_rate_limits 表（01 架构 §6） |
| backend | 本地构建（hyperf-swoole） | 9501 | ✅ | 应用；启动执行 migration + seed |
| frontend | 本地构建（nginx + vue dist） | 8080 | ✅ | 静态资源 + `/api` 反代到 backend |
| sms-mock | 本地构建 | 9502 | dev 必需 / prod 不启用 | 短信通道 mock（回显验证码，门禁 §3.4） |
| promtail | grafana/promtail:latest | — | 可选 | Docker stdout 采集 → Loki |
| loki | grafana/loki:3.x | 3100 | 可选 | 日志聚合 |
| grafana | grafana/grafana:11.x | 3000 | 可选 | 日志/指标面板与告警 |

> 本地一键启动（dev，含日志栈）：`docker compose up -d`；仅核心服务：`docker compose up -d mysql redis backend frontend`（sms-mock/promtail/loki/grafana 按 profile 拆分）。

### 2.1 初始化顺序（backend 启动脚本保证）

```
backend 容器启动
  1. wait-for mysql:3306 就绪（重试 60 次 × 2s）
  2. php bin/hyperf.php migrate        # 幂等：同库执行记录版本，重复执行安全（03 §6）
  3. php bin/hyperf.php db:seed        # 幂等：仅演示账号不存在时插入
  4. 启动 Swoole Server（9501）
```

- seed 内容：演示账号 `demo / Demo@123456`（密码 bcrypt 入库）、默认 OAuth/KYC 提供商 mock 配置
- MySQL 初始化：`MYSQL_DATABASE=mem_reg`、`MYSQL_USER=app`（最小权限：库内 DML + 审计表只读专用账号 `app_audit` 见 04 §7.1）、`MYSQL_ROOT_PASSWORD` 仅容器内部可用（宿主暴露的 3306 建议限制来源）

### 2.2 前端构建与发布

- `frontend` 镜像多阶段：`node:20-alpine` 构建 `dist` → `nginx:alpine` 托管 + 反代配置（`/api` → backend:9501，`/api/v1/auth/refresh` 等 Cookie 路径一致）
- nginx 安全头（04 §6.1）在 `default.conf` 统一配置；`client_max_body_size 10m`
- 静态资源带指纹缓存；`/index.html` 不缓存

## 4. 日志体系

### 4.1 输出约定（Compose 与 K8s 同构）

- **应用日志只写 stdout**（容器内不落盘文件）——K8s 与 Compose 用同一套采集路径，无需改造
- 全部 JSON 行（`LOG_JSON=true`），字段表：

| 字段 | 示例 | 说明 |
|---|---|---|
| `time` | `2026-08-17T10:00:00+08:00` | ISO8601 含时区 |
| `level` | `info` / `warning` / `error` | — |
| `message` | `login_success` / `refresh.reuse_detected` | 短事件名 |
| `request_id` | `7f3a…` | 全链路关联（02 §1.1） |
| `user_id` | 1001 | 可空 |
| `action` | `auth.login_success` | 与审计 action 同名（04 §7.1） |
| `ip` / `ua` | `1.2.3.4` | 脱敏处理 |
| `extra` | `{"login_type":2,"is_unusual":true}` | 业务上下文 |
| `duration_ms` | 23 | 性能 |

- **禁止**在日志输出：密码、验证码、完整证件号、Cookie 原文（04 §7.2，日志过滤器兜底）
- nginx access_log 同样 JSON（nginx json_log_format），含 `request_id`（透传 `X-Request-Id`）

### 4.2 Promtail → Loki → Grafana

- **promtail**（Docker 驱动 `--log-driver` 或 `loki` Docker plugin）：
  - `scrape_configs`：`docker_sd_configs` + `relabel_configs` 打服务标签 `service="backend"|"frontend"`、`compose_service="mem-reg-backend"`
  - K8s 演进为 DaemonSet，标签 `namespace/pod/container`（§7）
- **loki**：单实例（dev）；prod 可按量启 `memberlist` 集群或托管方案；保留期 `retention_period=30d`
- **grafana**：预置数据源 + 面板 JSON 导入（`deploy/grafana/dashboards/`）：
  - 登录成功率（sc_login_logs 事件聚合）：`sum(rate({service="backend"} | json | action="auth.login_success"[5m]))`
  - 限流/锁定（429/423 计数）、KYC 状态流转、refresh 重用检测、接口 P95 延迟、5xx 错误率
  - 告警规则：登录成功率 < 60% 持续 5 分钟 → 告警；`refresh.reuse_detected` 任一 → P0 告警；锁定次数 > 阈值 → 风控提示

### 4.3 指标（预留）

- Swoole 进程指标（worker 内存、协程数）经 Prometheus 格式暴露（`/metrics`，生产关闭或加鉴权）；Grafana 同栈展示
- 业务指标优先从日志事件聚合（避免额外埋点成本），登录/限流/审计事件已覆盖

## 5. 监控与告警

| 类别 | 指标 | 告警阈值（示例） | 通道 |
|---|---|---|---|
| 可用性 | 接口 5xx 率 | >1% 持续 5 分钟 | 邮件 / 钉钉 webhook（Loki 告警） |
| 安全 | 登录失败率 | >40% 持续 5 分钟 | P0 邮件 |
| 安全 | refresh 重用检测 | 任一 | P0 邮件 + 审计 |
| 安全 | 账号锁定次数 | >10/小时 | 邮件 |
| 业务 | 短信通道失败率 | >5% | 邮件 |
| 资源 | backend 内存/CPU | 阈值告警 | 宿主监控（可选） |

## 6. 备份与恢复

### 6.1 备份策略

- **每日全量**：`mysqldump --single-transaction --set-gtid-purged=OFF mem_reg` → 压缩 → 对象存储（保留 30 天）
- **实时增量**：MySQL binlog（`binlog_format=ROW`，保留 7 天）→ 可恢复至任意时间点
- **密钥**：`JWT_SECRET`/`TOTP_ENCRYPTION_KEY` 等随备份独立保存（丢失 = 全部 TOTP 密文不可解 + 会话不可验证）
- 备份脚本：`deploy/backup/backup.sh`（cron 每日 02:00），恢复演练每季度一次（04 §9 清单项）

### 6.2 恢复流程

```
1. 停写：后端切只读（或暂停入口）
2. 恢复最近全量 dump → 应用 binlog 至目标时间点
3. 校验：演示账号登录 + 随机业务行抽样
4. 恢复入口；确认审计表完整性（只追加表不受影响）
```

## 7. K8s 演进

### 7.1 迁移差异点（相对 Compose）

| 项 | Compose | K8s | 差异动作 |
|---|---|---|---|
| 密钥 | `.env` | Secret（`app-secrets`，键与 `.env` 同名） | 逐键映射，禁止 ConfigMap 放密钥 |
| 配置 | `.env` | ConfigMap（`app-config`） | 仅非敏感项 |
| MySQL | 容器 | 建议托管 RDS / 云 MySQL（有状态组件不自运维） | 连接串走 Secret；保留 binlog |
| Redis | 容器 | 建议托管（或单点 + 降级） | 限流降级 sc_rate_limits 表兜底 |
| 后端 | compose service | Deployment + **HPA**（CPU 70% / 日志事件触发可选） | 无状态可多副本；Refresh 轮换依赖 DB（`FOR UPDATE`）保证并发安全，多副本无冲突 |
| 前端 | nginx 容器 | Deployment + Service（Ingress TLS） | 同镜像，无需改动 |
| 日志 | promtail 容器 | **Promtail DaemonSet**（/var/log/pods 采集） | stdout JSON 格式不变，仅标签不同（§4.2） |
| 可观测 | grafana/loki 容器 | 同栈（Loki 可托管） | 面板 JSON 复用 |

### 7.2 水平扩缩容要点

- backend 无状态（会话在 Cookie + DB），可安全扩到 N 副本；HPA 按 CPU 与 RPS
- Swoole 常驻内存：滚动更新用 `maxSurge=1 maxUnavailable=0`，优雅下线（`SIGTERM` → 停止接收连接 → 排空协程）
- 定时/队列任务：async-queue 消费端独立 Deployment（避免与 API 进程争抢），consumer 按队列 lag 伸缩
- 数据库连接池按副本数配比（`pool.max` 与实例数联动），防连接风暴

### 7.3 K8s 安全基线（上线检查）

- Secret 启用 KMS 加密（托管集群默认）；RBAC 最小权限
- NetworkPolicy：backend 仅允许来自 frontend-ingress 与 redis/mysql 网段
- 镜像扫描（trivy）+ 不可变 tag 部署；Pod `securityContext`（只读 rootfs、非 root 运行）
- PodDisruptionBudget：`minAvailable: 2`

## 8. FAQ

**Q1 一键启动起不来，MySQL 一直在 retry？**
等依赖就绪的 `wait-for` 重试上限 120s；首次拉镜像耗时，可 `docker compose pull` 预热。确认宿主 3306/6379 未被占用（端口冲突改 `.env` 映射）。

**Q2 短信验证码收不到？**
dev 用 sms-mock：验证码在接口响应 `data.mock_code` 与 sms-mock 日志回显（仅 dev，04 §门禁）。prod 检查 `SMS_PROVIDER` 与密钥、通道配额。

**Q3 生产日志不落文件，怎么看？**
Loki（`logcli query '{service="backend"}`）或 Grafana Explore。容器级：`docker compose logs -f backend`。

**Q4 换环境后旧设备还能登录吗？**
`JWT_SECRET` 变化会使已签发的 Access/TOTP 票据失效，但 Refresh（哈希存库）与 device_key 不受影响——**更换生产密钥需通知全部用户重新登录**（或接受 15 分钟 Access 窗口）。

**Q5 本地 Windows（Docker Desktop）性能注意？**
MySQL 数据卷建议挂命名卷（非 bind mount 到 NTFS），Swoole 在容器内不受宿主影响；文件变更热重载用 Hyperf `-d` 监听即可。

**Q6 多副本下 Refresh 并发刷新会冲突吗？**
不会：轮换在事务内 `FOR UPDATE` 设备行串行化，同一 token 只会被一个副本轮换成功（01 架构 D1 / 04 §3.4）。
